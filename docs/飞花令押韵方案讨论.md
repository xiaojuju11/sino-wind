## 决策结论（2026-10-15 确认）

**采用 1B + 2B：**

| 项 | 结论 |
| :--- | :--- |
| **1B** 玩家侧 | 逐句合规 —— 每句韵脚只需被平水韵收录即通过，**可自由换韵**，不再跨轮锁死 |
| **2B** 先贤侧 | **优先同韵**（含令字 + 与玩家本句同韵 + 作者优先）；同韵句耗尽时放宽为任意韵脚，**不判负** |

## 一、为什么需要讨论

现有实现把「本轮首个有效句的韵部」**锁死为整局韵部**，此后任何不同韵的句子直接判负。
实测这条规则会**用正确名句反被判负**：

```
令字 = 月，开局未指定韵部
  ① 提交「举头望明月」  → ✅ 通过；系统把本局韵部锁为「入声六月」（月的韵脚）
  ② 提交「床前明月光」  → ❌ 判负！原因：句末不属本局「入声六月」
                          （「光」属「下平声七阳」，是正确名句）
```

玩家若不背熟题库，**无从得知第一句把韵锁成了什么**，只能靠猜。

## 二、根因：题库被 106 个韵部切碎

平水韵有 106 个韵部，而题库仅 **483 句**（来源：`backend/src/data/feihuaPoems.js` 合并
`feihuaCorpus.js`）。平均每韵部只有约 **4.5 句**。

按「令字 + 韵部」交叉统计（数据由 `proof/diag-rhyme-distribution.cjs` 生成）：

| 令字 | 含字总句 | 涉及韵部数 | 最大韵部可用句数 | 仅 1 句的韵部 | **≥8 句可开局的韵部** |
| :--- | ---: | ---: | :--- | ---: | ---: |
| 花 | 34 | 25 | 六麻 5 | 14 | **0** |
| 月 | 40 | 23 | 六月 10 | 14 | **1** |
| 春 | 30 | 33 | 六麻 2 | 26 | **0** |
| 风 | 33 | 25 | 一东 6 | 17 | **0** |
| 夜 | 23 | 20 | 七麌 3 | 13 | **0** |
| 酒 | 15 | 7 | 二十五有 7 | 3 | **0** |
| 云 | 16 | 17 | 十五删 3 | 13 | **0** |
| 雨 | 16 | 14 | 八庚 3 | 9 | **0** |
| 山 | 35 | 27 | 十五删 7 | 18 | **0** |
| 水 | 21 | 19 | 十一尤 4 | 16 | **0** |

> **合计：210 个「令字 + 韵部」组合中，只有 1 个（0.5%）的可用句数达到 8 句。**

结论：**在现有题库规模下，"严格同韵"几乎无法开局。**

## 三、四个候选方案

### 1A —— 完全取消押韵

**规则**：含令字 + 在题库中 + 未重复 = 通过。不看韵脚。

| | |
| :--- | :--- |
| 玩家体验 | 最流畅，可选句数 = 含令字总数（15~40 句） |
| 优点 | 零误判；实现最简单；不会因韵部卡死 |
| 缺点 | 失去飞花令「同韵唱和」的文学内核；与任务书「押韵校验」要求不符 |
| 与任务书关系 | ⚠️ 不符（任务书明确要求「平水韵/现代拼音韵脚合规性校验」） |

### 1B —— 逐句合规（可自由换韵）

**规则**：**每一句**的韵脚只需能被平水韵收录即通过；**不要求**与上一句同韵。
先贤答句尽量同韵，实在没有则放宽（否则先贤会无句可应）。

| | |
| :--- | :--- |
| 玩家体验 | 流畅；可选句数 = 含令字总数 |
| 优点 | 保留「韵脚合规性校验」（符合任务书字面要求）；不误判；可自由换韵不会踩坑 |
| 缺点 | 已不是严格意义的「同韵」游戏；需要额外处理先贤答句的韵 |
| 与任务书关系 | ✅ 符合「韵脚合规性校验」字面要求 |

### 1C —— 开局显式选韵 + 严格同韵

**规则**：开局必须选一个韵部，双方都只能出该韵的句子。

| | |
| :--- | :--- |
| 玩家体验 | 最"正统"，但**当前题库下几乎开不了局** |
| 优点 | 最贴近真实飞花令 |
| 缺点 | 🔴 **致命**：仅 1/210 组合可用；「花/春/风/夜/酒/云/雨/山/水」全部 0 个可开局韵部 |
| 前提条件 | **必须先把题库扩充到每个韵部 ≥15 句**（约需 106×15 ≈ 1600 句，现状 483 句，需扩 3 倍以上） |
| 与任务书关系 | ✅ 最符合 |

### 1D —— 选韵时先提示可用句数

**规则**：同 1C，但在开局界面显示「本令字 + 本韵部共 N 句可用」，N 过少则禁用该组合。

| | |
| :--- | :--- |
| 优点 | 玩家不会踩坑 |
| 缺点 | 治标不治本 —— 禁用后玩家会发现**几乎无可选项**（见 1C 数据） |
| 与任务书关系 | ✅ 符合，但体验受限于题库规模 |

## 五、附带需要一并决定的点

押韵方案定了之后，下面两点会随之变化：

1. **先贤（AI）答句是否也必须同韵？**
   实测：若强制先贤同韵，令字「月/山/夜」会在**第 1 轮**就因同韵句耗尽而显示
   「先贤无可应之句，雅士胜出」—— 玩家白赢一局。

2. **「韵脚无法判定」时如何处理？**
   现行为：不判负，只提示「此句未收录于本局经典题库」，计时继续。

| **答辩/演示时顺畅可玩** | **1B** —— 保留押韵校验（符合任务书），但不因换韵误判负 |

## 八、实现结果（1B + 2B）

### 8.1 原误判负场景已修复

```
令字 = 月，开局未指定韵部
  ① 「举头望明月」→ 轮次 1  先贤应「举杯邀明月」      同韵[入声六月] ✅
  ② 「床前明月光」→ 轮次 2  先贤应「小时不识月」      按 2B 放宽（同韵句耗尽）
  ③ 「海上生明月」→ 轮次 3  先贤应「长安一片月」      同韵[入声六月] ✅
  ④ 「明月松间照」→ 轮次 4  先贤应「明月来相照」      同韵[去声十八啸] ✅
  ⑤ 「月落乌啼霜满天」→ 轮次 5  先贤应「明月何时照我还」同韵[下平声一先] ✅
```
第 ② 句不再判负 —— 这正是本次修复的核心。

### 8.2 押韵校验仍然保留

| 场景 | 行为 |
| :--- | :--- |
| 韵脚可被平水韵收录（单一韵部） | ✅ 通过 |
| 韵脚可被平水韵收录（多韵部） | ✅ 通过（不再要求指定韵部） |
| 韵脚**完全未被平水韵收录** | 不判负，给提示「句末一字未见於平水韵」，计时继续 |
| 句末不含令字 / 同局重复 / 跨局重复 | ❌ 判负 |
| 开局**显式指定**韵部后提交异韵句 | ❌ 判负（向后兼容保留严格模式） |

### 8.3 可玩性（每令字 200 局，玩家随机挑句）

| 令字 | 平均轮数 | ≥3 轮 | ≥5 轮 | 玩家白赢 | 先贤胜 | 和局 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 花 | 5.01 | 180/200 | 144/200 | **0** | 77 | 123 |
| 月 | 5.15 | 186/200 | 154/200 | **0** | 74 | 126 |
| 春 | 4.71 | 178/200 | 122/200 | **0** | 98 | 102 |
| 风 | 4.89 | 178/200 | 139/200 | **0** | 83 | 117 |
| 山 | 4.86 | 177/200 | 134/200 | **0** | 87 | 113 |
| 水 | 4.56 | 177/200 | 113/200 | **0** | 118 | 82 |

> 上限 6 轮。**「玩家白赢」全为 0** —— 先贤每次都能应句，不再出现"第 1 轮即结束"。
> 夜/酒/云/雨 四字当前不在白名单（属决策点 5），未参与统计。

### 8.4 跨局去重（任务书「严禁双方重复报同一句诗」）

原实现只做**同局**去重，换一局可重复用同一句。现补充**跨局**去重：

- 开局时由 `feihuaController.loadPlayedLines()` 查该用户最近 20 局，抽取其历史提交过的诗句
  （normalize 后去重，上限 800 条）注入 `game.playedLines`
- 再次提交历史用过的句子 → 判先贤胜，原因「此句此前已用过」
- **仅对登录用户生效**：访客的 `guestKey` 是开局后才生成的，开局时无法回查历史；
  访客仍受单局去重保护

实测（自签 JWT，`proof/verify-feihua-dedup.cjs`）：
```
第一局  提交「举头望明月」→ 写入历史
第二局  开局注入历史 1 条且含该句 ✅ → 重复提交 → finished / winner=sage ✅
第三局  提交未用过的「海上生明月」→ 正常 playing ✅
```
