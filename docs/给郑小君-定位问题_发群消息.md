## 长版（若需要附证据）

**@郑小君 一个已上线的定位 bug，附实测证据**

### 现象

「自动感知驻足城市」不生效，永远显示默认的临安（杭州）。

### 根因（三处，均实测）

**① pconline 无 CORS 头（致命）**

```js
const resp = await fetch('https://whois.pconline.com.cn/ipJson.jsp?json=true')
```

实测响应头：
```
HTTP 200
Access-Control-Allow-Origin: （未声明）
```

浏览器内（Chrome DevTools Protocol，页面上下文）：
```
TypeError: Failed to fetch
```

> 注意：本机 `npm run dev` 是 `http://localhost`，可能让人误以为"同源所以没事"，
> 但 CORS 与同源是两回事 —— 缺 ACAO 头时浏览器会直接拒绝。

**② 备选是明文 HTTP（致命）**

```js
const resp = await fetch('http://ip-api.com/json/?lang=zh-CN')
```

HTTPS 部署后会报：
```
Mixed Content: The page at 'https://…' was loaded over HTTPS,
but requested an insecure resource 'http://ip-api.com/…'
```
该接口 HTTPS 版需付费。另外它中文也是乱码：`"country":"ä¸å½"`。

**③ GBK 未解码（次要但污染缓存）**

```js
const json = await resp.json()   // 默认 UTF-8
```

实测：
```
按 UTF-8 解 → city = "�Ž���"      ← 当前
按 GBK  解 → city = "九江市"      ← 正确
```

拿到乱码后 `matchAncientCity("�Ž���")` 匹配不到任何城市，走「地域兜底」分支
返回 `{ name: '�Ž���', ancient: '九州·�Ž���' }`，**并被写入
`localStorage.gufeng_detected_city_cache` 缓存 12 小时** —— 刷新也恢复不了。

### 后果

三条都失败 → `return TOP_ANCIENT_CITIES[0]` → 恒为杭州。

### 改法（一次解决三问题）

```js
const IP_PROVIDERS = [
  { url: 'https://ipwho.is/',      pick: (j) => (j.success === false ? '' : (j.city || j.region || '')) },
  { url: 'https://ipinfo.io/json', pick: (j) => (j.city || j.region || '') },
]
for (const p of IP_PROVIDERS) {
  try {
    const controller = new AbortController()
    const timer = setTimeout(() => controller.abort(), 2500)
    const resp = await fetch(p.url, { signal: controller.signal })
    clearTimeout(timer)
    if (!resp.ok) continue
    const cityName = p.pick(await resp.json())
    // 缓存前校验可读，避免把脏数据存 12 小时
    if (!cityName || /[\uFFFD]|[^\u4e00-\u9fa5A-Za-z0-9·\-\s]/.test(cityName)) continue
    const matched = matchAncientCity(cityName)
    localStorage.setItem('gufeng_detected_city_cache', JSON.stringify({ timestamp: Date.now(), data: matched }))
    return matched
  } catch { /* 换下一个 */ }
}
return TOP_ANCIENT_CITIES[0]
```

### 临时的兜底（我不改你的文件，只在我的整合层加了一道防御）

我分支里已经加了一道校验：`autoDetectUserCity` 返回的城名若含替换符或非中日韩字符，
就直接弃用、转走我那边的 `locate()`。这样**根因修好前线上至少不会出现乱码城市名**。
