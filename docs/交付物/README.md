## 复跑方式

```bash
# 依赖：python-docx（排版）、Pillow（图片等比处理）
python gen1_作品介绍.py
python gen2_AI使用情况.py
python gen3_素材与版权.py

# DOCX → PDF（使用捆绑 LibreOffice，不用系统安装版）
node <libreoffice-kit>/cli.js convert --input 作品介绍文档.docx --output 作品介绍文档.pdf
```

## 事实来源与撰写原则

三份文档的每项数据均来自**仓库实测或只读审计**，来源包括：

- 依赖许可：读取各依赖包实际安装目录下 `package.json` 的 `license` 字段，非按包名推断
- 代码与文档规模：`proof/diag-code-size.mjs` 实测
- 功能验证：浏览器实机走查、接口实测、数据库查询
- AI 使用情况：`docs/handovers/` 下 38 份开发交接与 AI 使用填报记录
- 素材来源：素材 README、填报记录，以及全仓递归检索

**撰写原则（按任务要求执行）：**

1. **严禁把规划当成果**。凡未实现或未验证的能力，均单列小节标注，不列入「已完成」。
2. **主动披露负面事实**，包括：
   - Coze 拍照识器工作流上游已返回 404，真实多模态识别当前不可用（实测三处端点变体）
   - 主干存在 1 处预存 lint 报错（在他人负责文件内，本作品未擅自改动）
   - 测试数据中用户 ID=2 的 `rank_level` 为历史脏数据（转义串未反转义）
   - 模型响应时延部分环节未达早期验收口径
   - README 所列接口与实际路由存在滞后
3. **不夸大人工占比**。仓库内无任何文件声明某模块为纯人工手写，故文档不主张「代码全部自研」，改以「人均占比 + 具体裁定与修正条目 + 自建数据与脚本规模 + 自测证据」举证。
4. **证据不足即标注待确认**，不作推断性结论（素材合规清单共列出 13 项待人工确认事项）。
