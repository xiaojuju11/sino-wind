## 🛠️ 二、 详细任务规格与技术标准

### 任务 1：大模型 Server-Sent Events (SSE) 流式传输管道
* **技术痛点**：目前知音先贤对席（`ScholarChat`）为单次 HTTP POST 请求，先贤回复长篇诗论需要阻塞等待 3~5 秒，严重影响交互体验。
* **开发要求**：
  1. **后端重构** (`backend/src/controllers/deepseekController.js` & 路由)：
     - 新增或改写先贤对席接口为 SSE 协议（`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`）；
     - 将 DeepSeek 官方流式 Chunk 实时推送给前端客户端，保持反出戏熔断机制生效；
  2. **前端流式解析** (`frontend/src/pages/ScholarChat.jsx`)：
     - 基于 `fetch` + `ReadableStream` 接收事件流；
     - 实现**逐字渗润水墨打字机动效**（字符从淡透明到湿润定型），消灭空白等待感。

### 任务 2：先贤知音「飞花令」诗词竞技对弈引擎（状态机）
* **技术痛点**：知音模块目前仅有人机闲聊，缺乏竞技深度与玩法闭环。
* **开发要求**：
  1. **设计回合制对弈状态机**：
     - 开局设定令字（如“月”、“花”、“春”、“风”、“夜”）；
     - 倒计时机制（每回合 30 秒倒计时）；
     - 玩家输入诗句 ➔ 自动合规校验 ➔ 先贤大模型依据上一句接出对应唐诗宋词 ➔ 胜负判定与轮转；
  2. **核心裁决算法**：
     - 令字命中检测：输入的诗句必须精准包含本轮令字；
     - 查重机制：同一局内禁止复读已经出现过的诗句；
     - 诗库验证：确保是真实的古典诗词，防止玩家胡乱输入假句子；
  3. **数据闭环联动**：获胜或平局自动将对弈数据同步沉淀至书斋修持数据（`debate_count` 自动自增）。

### 任务 3：纯前端《翰林通关文牒 / 敕命诏书》Canvas 2D 生成引擎
* **技术痛点**：修持等级提升后缺乏实体感与分享驱动力。
* **开发要求**：
  1. **严禁调用 html2canvas**（避免模糊错乱），使用原生 Canvas 2D 手写长图渲染管线；
  2. **古典竖排排版算法**：
     - 文字从右向左、从上至下垂直排布；
     - 处理标点避头尾算法（逗号、句号不得作为行首）；
  3. **动态贝塞尔篆刻印章**：
     - 根据用户雅士昵称、日期与称号，通过三次贝塞尔曲线算法动态生成朱砂印泥篆刻印章；
  4. 支持导出 2x Retina 高清海报（WebP/PNG）并集成原生 Web Share API。
