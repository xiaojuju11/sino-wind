## 二、逐项说明

### 1. 城邑志改为独立二级页面（`3c81b5c`）

**需求**：用户在预览里指出「这个时间以及地点的展示不应该放在最下面，可以做一个二级页面」。
原实现是首页底部 Popup 抽屉，朝代沿革轴被压在抽屉下半部，阅读体验差。

- 新增 `pages/CityChroniclePage.jsx`，顶级路由 `/city-chronicle`（不套 Layout，与 `/poem` 同族）
- 新增 `styles/cityChronicle.less`；内容区沿用 `home-chronicle__*` 类，避免重复定义
- Home 的点击由「开弹窗」改为「跳转」，删除 `chronicleOpen/chronicleQuery` 状态与 70 行弹窗代码
- 交接方式：进入页面时把当前城邑写入 `sessionStorage`，页面打开即展示它；
  留驻时写回并返回首页，首页**挂载时消费**该键

**过程中修掉两个真 bug**（均实测复现后修正）：
- 原用 `window` 事件回传，但页面在 `navigate()` **之前**同步派发 —— 那一刻 Home 尚未挂载、
  监听器不存在，事件直接丢失（实测：留驻成都后首页仍是香港）。改为挂载时读 `sessionStorage`
- 消费留驻的 effect 与 IP 定位 effect 同时跑：先应用「成都」，稍后 IP 返回「香港」**把它覆盖**
  （实测等 8 秒后被改回）。加 `manualPickRef` 守卫，定位链路见到标记即放弃写入

### 2. 按钮规范统一（`9916adc`）

**需求**：「button 过于 AI，需要添加一定的圆角以及阴影」。

**原状不统一**：圆角 6px / 7.8px 混杂；只有「收入宝鉴」有外阴影，拍照/上传/发音/音色
全是纯内描边（观感发平）；配色三套并存（单色实底 / **渐变**实底 / 透明幽灵）。

- 新增 `styles/buttons.less`：一处定义、两处组件共用
- **双色**：朱砂（主要动作）/ 竹青（仅完成态）；泥金只作描边与图标
- **去掉渐变** —— 渐变是「AI 味」的主要来源
- 圆角 10px（小按钮 8px）；外阴影用**暖褐调** `rgba(90,44,30,·)` 而非纯黑
- 覆盖 7 个按钮：返回 / 拍照 / 上传 / 预览清除 / 发音 / 音色切换 / 收入宝鉴

### 3. 展卷细读按钮（`457f3e7`）

**需求**：「跳转按钮不能是一个箭头，上面写文字『展卷细读』字样」。
原 `aria-label` 已写「展卷细读」，只是从未显示 —— 现转为可见文字。

**合并说明**：主干同期也做了同一改动（`f4ef9b5`），但其实现用 `<div aria-label>` ——
不可键盘聚焦、对读屏器仅是标签而非控件。合并时**保留 `<button>` 语义**，
子元素改用主干的 `__text` / `__icon` 类名以套用其样式。

### 4. 样式层治理（`d0e5efe`）

**背景**：本次「展卷细读」按钮一度只有 25×27px，根因是**精修层静默覆盖**。
用户追问「还有什么 bug」后系统审计，结论比预想更系统：

- **精修层静默覆盖基础层**（`referencePolish.less` / `referenceFidelity.less`）：
  无 `!important`、无提示地改掉尺寸与定位 → 改基础文件不生效。人工抽查确认 12 处
- **两套单位体系并存**：基础层用 rem 的类名 105 个、精修层用 px 的 139 个，
  **重叠 35 个** —— 同一元素被两套单位各写一次，缩放行为不一致
- `home.less` 自身已成补丁堆：2537 行 / 278 个规则头，同文件内
  `.home-yayan-input-box` 定义 **20 次**、`.home-yayan-result-card` 17 次、
  `.home-yayan-submit-btn` 16 次（box-shadow 写 4 遍）

**本次只做低风险的第 1 步（零视觉变化）**：
- 两个精修层文件头各加「本层覆盖清单」
- 基础层 9 处就地加 `// ⚠️ 精修层覆盖：…` 警示
- 删除 `.home-poem-more` 的重复单行块
- **未改动任何生效值**

**零视觉变化的证据**（新增脚本）：
```
390×844 视口 · 冻结动画 · 19 个选择器 × 26 个关键属性
改前 494 项 vs 改后 494 项 → 一致 494 · 差异 0
```

> 注：`theme.less` 的覆盖是**有意设计**（暗色模式统一替换，带 `!important`），
> 不在标注范围，也不建议改动。

### 5. 定位防御的判据更新（含在 `1530368`）

主干 `11b5efa` 已修复我提交的定位 bug（pconline 无 CORS + GBK → 换 `ipwho.is`）。
故把我此前那道防御的注释改写为准确表述，并明确其**第二道、也是更常触发**的判据：

1. 城名可读（防未来再接入 GBK 源污染 12 小时缓存）
2. 城名必须能落到本项目 359 城城邑库

第 2 条本次实测就触发了：本机 IP 被判为海外，`ipwho.is` 返回「新加坡」，
虽可读但库中无此邑，不拦会得到「九州·新加坡」。验证：现落回「崖州（三亚）」。
