## 一、 参赛提交四大合规红线（必须整改事项）

在将材料与作品打包提交前，团队必须确保以下 4 项合规调整落实到位：

### 1. 匿名化红线（⚠️ 绝不可泄露身份信息）
- **大赛条款**：提交专家评审的材料**原则上按赛事匿名化要求处理，不填写参赛学校、团队成员和指导教师等可识别身份的信息**。
- **自查与整改**：
  - 申报 Word/PDF 文档正文中，**严禁出现学校全称、简称、团队成员真实姓名、学号及指导老师姓名**。
  - 文中涉及人员一律使用身份代称（如：“队长”、“前端开发成员”、“后端开发成员”、“视觉设计成员”）。
  - 文档内引用的文件路径或终端截图，严禁暴露包含个人名字的绝对路径（如 `C:\Users\姓名\...`），统一脱敏处理为相对路径 `sino-wind/...`。

### 2. 清理冗余参考截图（⚠️ 杜绝版权歧义）
- **大赛条款**：使用第三方素材需取得合法授权，网络下载或标注“免费”不代表可随意使用。
- **自查与整改**：
  - 项目早期在 `frontend/public/assets/auth/` 中存放了 `reference-login.png` 和 `reference-register.png`（约 4.2MB），属于开发初期的参考设计稿截图。
  - **当前全站代码已完全零引用这两张图片**。为杜绝评审专家在解压静态包时质疑参考稿版权，**在最终参赛包交付前，必须直接从代码仓库的 public 目录中删除**。

### 3. 素材定性标准统一（⚠️ 古画真迹 vs AI生成不可混淆）
- **大赛条款**：必须明确区分“学生原创”、“AI生成或辅助生成”、“第三方授权/公有领域”，严禁将第三方或AI生成成果直接包装为学生独立原创。
- **自查与整改**：
  - **传世名画/历史图卷**（如魏晋雅集长卷、韩熙载夜宴图局部、传统水墨李白立绘）：统一定性为**“公有领域（Public Domain）中国传世古代书画藏本”**，由团队进行了“局部数字化裁剪、宣纸质感融合与色调统一”。
  - **AI 辅助生成图**（如 `scholar-scenes/` 7幅诗境背景、`scholar-portraits/` 头像）：统一定性为**“AI 辅助生成基础图样 + 学生手工去噪、修整构图、WebP 性能优化”**。
  - **严禁**把 AI 图说成“学生纯手绘”，也**严禁**把古画说成“学生原创设计”。

### 4. 移除功能的文档同步（⚠️ 保证“文实相符”）
- **大赛条款**：材料须真实反映作品当前的最终成果状态。
- **自查与整改**：
  - 项目现已彻底移除了全站的语音朗读与语音合成按钮（保证各终端纯净流畅与移动端兼容）。
  - **文档中切勿残留“语音朗诵”、“TTS服务器”等描述**，避免专家实测时因“文档有写、页面没有”而扣分。统一口径为：“作品专注于纯粹典雅的古典文学研习，采用纯算法 Canvas 2D 粒子系统与纯代码 Web Audio 五声音阶交互音效，未采用外部语音合成大模型。”

### 3. 代表性 AI 使用过程（精选 3 大环节）

#### 【环节一：先贤对席对话的角色赋魂与反出戏熔断机制】
- **使用环节及目的**：用户在“知音”模块与李白、苏轼、李清照等历史名仕对话，要求模型具备高度沉浸的第一人称历史语感，且绝不打破虚拟角色设定。
- **主要工具／模型**：DeepSeek 官方 API（`deepseek-flash` 模型，基于 SSE 全双工流式传输）。
- **主要输入或素材来源**：用户输入的提问文字 + 后端注入的先贤生平典故与个性化设定。
- **AI 主要输出**：半文言风格的文学性回帖内容。
- **学生筛选、修改或再创作**：
  1. **分层 Prompt 架构**：团队设计了“人物层（性格与生平）+ 禁令层（禁止自称AI或助手）+ 铁律层（完全角色代入）”的 Prompt 体系。
  2. **编写出戏熔断器（`sanitizeSageReply`）**：针对大模型偶尔出现的元话语（如“我是一个人工智能”），自主编写正则表达式清洗器，强制截断并重写为先贤本人口吻的反驳文案（覆盖 7 位先贤 × 10 类身份质询，实测出戏率为 0）。
  3. **搭建 SSE 流式引擎**：自主实现后端心跳检测、背压处理与客户端断开上游取消逻辑。
- **最终成果中的应用位置**：前端“知音对席（`ScholarChat`）”页面。

#### 【环节二：白话雅译的 Prompt 设计与离线均匀散列兜底】
- **使用环节及目的**：用户输入现代白话（如“今天天气很好，我去公园散步”），系统输出古典名句、出处及现代释义。
- **主要工具／模型**：DeepSeek deepseek-flash（强制 JSON 结构化输出）。
- **主要输入或素材来源**：现代白话语句输入。
- **AI 主要输出**：包含 `ancient`、`author`、`explanation` 字段的 JSON 数据。
- **学生筛选、修改或再创作**：
  1. **Prompt 角色定义纠偏**：将模型角色由“翻译器”调优为“文学院士”，有效解决直译生硬问题，大幅增强对仗与用典典雅度。
  2. **离线兜底散列算法**：早期版本在网络异常或未命中时容易固定返回第一条，团队自主扩展了 20 条经典离线典库，并编写了基于输入文本 Hash 的稳定散列算法，实现“相同输入稳定输出、不同输入均匀离散”，彻底解决 AI/网络异常时的体验崩塌。
- **最终成果中的应用位置**：首页“白话雅译”模块与书斋“文人笔记”。

#### 【环节三：生成式 AI 辅助视觉生产与严格的人工规约】
- **使用环节及目的**：为移动端界面提供契合两宋审美特征的淡彩水墨插画背景与意境视觉。
- **主要工具／模型**：Image 2.0（内置图像生成大模型）。
- **主要输入或素材来源**：包含宋画美学、留白构图、米色宣纸质感、无文字无图标要求的英文提示词。
- **AI 主要输出**：512×512 及 3:2 宽幅水墨概念图。
- **学生筛选、修改或再创作**：
  1. **立下三大人工规约**：“严禁 AI 直出图标位图（全部改用矢量库）”、“严禁 AI 编造未经考证的生平数据”、“AI 素材必须人工二创与标定”。
  2. **二次构图与修图**：人工剔除带现代商业仙侠感的不合格图样；手工使用卡片底色消除画面边缘细微噪点；针对移动端首屏加载需求，将所有图像无损转换为轻量化 WebP 格式。
- **最终成果中的应用位置**：知音对席专属场景背景、书斋菜单条饰图。

### 5. 学生原创贡献说明（评分关键：突出核心自研算法）

这是拉开与一般“套壳类”项目差距的关键章节，**必须重点阐明团队在纯算法与全栈系统开发上的自主原创工作**：

#### （1）完全由学生团队自主研发的核心算法与系统（零 AI 依赖）
1. **飞花令对战与押韵规则引擎**：
   - 100% 学生自主编写平水韵 106 韵部判定算法；
   - 建立 483 句精选飞花题库与严苛的“三级平仄降级选句逻辑”；
   - 运行时完全依靠纯本地算法判定胜负与流转，**零大模型依赖**。
2. **诗词格律与五维分析算法**：
   - 100% 学生自主编写格律判定代码，支持五言/七言绝句与律诗的平仄三级优先判定、替对粘规则核验；
   - 纯数学公式计算并生成五维雷达图评分，杜绝大模型随机评分。
3. **古代历法与节气天文推算**：
   - 100% 依据太阳视黄经天文数学公式进行本地计算，精准还原二十四节气与晨昏时辰。
4. **动态水墨物理渲染引擎**：
   - 基于 HTML5 Canvas 2D 纯代码编写粒子流体力学与正弦波叠加算法，动态模拟墨滴晕染与远山云气，**非 AI 生成的视频或预渲染动图**。
5. **国风微交互声效系统**：
   - 基于 Web Audio API，纯代码振荡器算法实时合成五声音阶（宫、商、角、徵、羽），**零外部音频素材依赖**。

#### （2）全栈工程架构与质量保障
- **高可用工程设计**：自研大文件分片哈希算法（SHA-256 采样加权 + 纯 JS 双模回退）、断点续传、JWT 双重令牌与两步恢复码安全认证。
- **工业级自动化测试**：团队自主编写了全覆盖的单元测试与集成测试，目前 **前端 87 项测试 + 后端 72 项测试 100% 通过（共计 159 项自动化测试）**，具备完整的软件工程自洽性。
