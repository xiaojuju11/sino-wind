## 恢复码接口与迁移（队友必须先做）

拉取代码后，在后端目录先执行，再重启服务：

```powershell
node scripts/init-account-recovery.js
node src/index.js
```

迁移可重复执行：新增 `users.recovery_code_hash`、`users.auth_version`、`auth_recovery_attempts`；原 `users.phone` 也存邮箱，扩至 VARCHAR(254)，保留原排序规则及唯一索引。不删除用户、收藏或业务记录。本机已完成迁移；其他成员/部署环境须分别执行。缺失新列时，身份校验会按503关闭，不能跳过迁移。

| 接口 | 请求 | 成功响应新增部分 |
| --- | --- | --- |
| POST `/api/auth/register` | 原注册字段 | 顶层 `recoveryCode`；原 code/message/user 保持 |
| POST `/api/auth/recovery-code` | 已登录，`{password}` 当前密码 | `{code:1,data:{recoveryCode}}` |
| POST `/api/auth/recovery/reset` | `{phone,recoveryCode,newPassword}` | `{code:1,data:{recoveryCode}}`，必须保存新码 |

- `phone` 沿用既有字段名，接受手机号及原前端支持的 qq/163/126/sina/gmail/foxmail 邮箱。注册与恢复统一去首尾空白和大小写；大小写变体共用限流。
- 恢复码为192位随机数，展示为8组6位十六进制，可输入空格/连字符。服务端仅保存 SHA-256 摘要；响应 no-store，不记录明码。
- 重置使用事务行锁：密码更新、恢复码换新、auth_version递增同时提交。同一旧码并发仅一次成功；全部旧Token（包括旧版无版本Token）失效。正常登录仍兼容原始Token和Bearer格式。
- 每种恢复操作独立限制：来源IP 30次/15分钟，账号5次/15分钟；数据库持久化，重启不清空。超过返回429与Retry-After；超过一天的旧窗口在后续请求中有界清理。
- 没有恢复码且已忘记密码的旧账号，需要团队核验，不能凭手机号/邮箱或图形验证码直接重置。普通修改密码保留原流程，增加版本及旧哈希条件更新以防覆盖并发恢复。
