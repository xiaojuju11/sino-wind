## 三、 人工筛选、修改、重构与二次创作过程（⚠️ 竞赛重点核验项）

### 1. 人工筛选与内容把关：
* **图标规范性核验与替换**：AI 初始代码中建议引入了 `BookOutline`，但在实际 Rollup 构建中该组件在特定版本库中不存在导致编译报错。本人手动排查 `antd-mobile-icons` 源码导出字典，精准筛选并替换为完全兼容且合规的 `FileOutline`，同时确保全量使用矢量组件，彻底杜绝违规死图片图标。
* **业务闭环逻辑把关**：剔除了常规电商式“购物车/收藏夹”生硬交互，将其升华为符合宋代士大夫书斋规制的“摘录于书斋”、“退卷归架”、“卷轴归架”雅致文案与弹窗反馈。

### 2. 视觉素材与长卷排版手工打磨（高强度人工工作量）：
* **上下传统木轴阴影手工编写**：通过手写双重伪元素与线性渐变 `linear-gradient(90deg, #5c4327 0%, #a48259 50%, #5c4327 100%)`，纯 CSS 拟真打造出古代木质轴头的光泽与微立体质感，无需加载任何外源重型图片，极大优化性能。
* **动态 rem 比例手工精校**：针对移动端视口（375px~412px），手工换算卡片留白、字号行距（`line-height: 1.8`），确保古诗正文对仗断句美观，绝不产生单字断行掉行。

### 3. 代码与系统的手工重构与编写（核心技术成果）：
* **模块化组件手写实现**：独立编写 `PoemCollection.jsx` 组件完整生命周期，设计了 `poems`、`searchKey`、`activePoem` 响应式状态机；
* **高质感 Less 样式工程手写**：手动编写 `poemCollection.less`（300+ 行），基于 `@color-seal: #9E2A2B`（朱砂红）与 `@color-gold: #C5A059` 构建视觉层次，手写了平滑淡入 `fadeIn` 与卷轴上浮 `slideUp` 动效；
* **路由体系与入口打通**：在 `App.jsx` 中注入新路由，并在 `MinePage.jsx` 中将旧占位 `Toast` 替换为真实无缝导航，彻底修复 Phase 1 遗留的交互短板；
* **双模容灾设计**：手写 `axios.get('/api/poem/my-list')`，并封装空值与异常状态自动降级到古典名篇，保障离线与演示环境下 100% 具备可展示性。
