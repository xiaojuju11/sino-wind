# 注册验证码 502：部署与验收

截图中的 502 表示网关未能取得上游有效响应，不能仅凭截图断定服务器根因。验证码接口不依赖数据库查询；应先检查后端启动与代理，而不是修改验证码校验规则。

## 本次调整

- 增加后端 `npm start` 正式启动入口，避免平台按惯例启动时提示缺少脚本。
- 将识景接口的 sharp 原生依赖改为按需加载。服务器未正确安装图像二进制时，不再因为这一可选功能导致整个后端启动失败。
- 提供 `deploy/nginx.conf.example`，统一转发到默认 3000 端口并保留 `/api` 前缀。
- 前端将网关错误显示为中文，保留验证码加载失败后的手动重试。

## 服务器更新

1. 拉取代码，在服务器的 `backend` 目录执行 `npm ci`（不要复制 Windows 的 node_modules），使用 Node.js 22 LTS。
2. 配置数据库和至少 32 字符的独立随机 `JWT_SECRET`。保留原有生产密钥，勿每次部署重新生成。参考 `backend/.env.example`；密钥缺失时后端会拒绝启动。
3. 使用现有进程管理工具重启后端，启动命令为 `npm start`，工作目录为 `backend`。代理端口必须与实际 `PORT` 一致，模板为 3000。
4. 在 `frontend` 执行 `npm ci`、`npm run build`，将 dist 配为站点目录。默认通过同源 `/api` 调用后端；Vite 的开发代理不会进入生产构建。
5. 将示例中的 location 规则合入实际 Nginx 站点，检查配置后重载；不要覆盖已有 HTTPS/域名设置。后端在另一个容器时，127.0.0.1 需替换为可达的后端服务地址。

## 验收与定位

先在服务器请求 `curl -i http://127.0.0.1:3000/api/auth/captcha`，再请求 `curl -i http://你的站点/api/auth/captcha`。两者均应为 HTTP 200，JSON 含 `code: 1`、`captchaId`、`captchaSvg`。验证码不应在代理/CDN 中缓存。

- 本机端口连接失败：检查后端进程日志、JWT_SECRET、依赖安装及端口占用。
- 本机成功而站点 502：检查 Nginx error.log 的 upstream 地址、端口、容器网络及访问权限。
- 接口成功后，在手机重新打开注册页，刷新验证码并完成注册；数据库迁移仍按 `docs/DB_MIGRATION.md` 执行。

本地验证不能替代服务器验收；如仍失败，请保留上述两次请求结果及对应后端/Nginx 错误日志（隐去密钥）。
